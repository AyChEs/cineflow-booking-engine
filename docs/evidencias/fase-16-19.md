### 3. Eloquent Models with Complete Relationships

#### Relationship Types Implemented:

**1:N (hasMany / belongsTo)**
- User hasMany Reservas
- Sala hasMany Sesiones
- Pelicula hasMany Sesiones
- Sesion hasMany Reservas

**N:1 (belongsTo)**
- Reserva belongsTo User
- Reserva belongsTo Sesion
- Sesion belongsTo Sala
- Sesion belongsTo Pelicula

**N:M (belongsToMany)**
- Pelicula belongsToMany Categorias
- Categoria belongsToMany Peliculas

#### Example Model with Relationships:

```php
class Pelicula extends Model
{
    protected $fillable = [
        'titulo', 'sinopsis', 'duracion_min', 
        'classificacio_edad', 'trailer_url'
    ];

    public function sesiones(): HasMany
    {
        return $this->hasMany(Sesion::class, 'fk_pelicula_id');
    }

    public function categorias(): BelongsToMany
    {
        return $this->belongsToMany(
            Categoria::class,
            'pelicula_categoria',
            'fk_pelicula_id',
            'fk_categoria_id'
        );
    }
}
```

### 4. Controllers Managing Relationships

#### Good Practices Applied:

✅ **Eager Loading** to avoid the N+1 problem
```php
$peliculas = Pelicula::with('categorias')->get();
$sesiones = Sesion::with('sala', 'pelicula')->get();
```

✅ **Validations with exists**
```php
$request->validate([
    'fk_sala_id' => 'required|integer|exists:salas,id',
    'categorias.*' => 'exists:categorias,id',
]);
```

✅ **N:M relationship management**
```php
// Create
$pelicula->categorias()->attach($request->categorias);

// Update
$pelicula->categorias()->sync($request->categorias ?? []);
```

✅ **PRG pattern (Post/Redirect/Get)**
```php
return redirect()->route('peliculas.index')
    ->with('success', 'Película creada correctamente.');
```

## 📊 Technical Decisions Made

### DT-01: Flexible Category System (N:M)
- **Date:** Week 17
- **Decision:** Implement an N:M relationship between Peliculas and Categorias
- **Rationale:** A movie can have multiple genres (e.g. Action + Science Fiction)
- **Impact:** Requires a pivot table and management via sync()

### DT-02: Preparation for Multi-Cinema
- **Date:** Week 17
- **Decision:** `fk_cine_id` field nullable in Salas
- **Rationale:** Allows working with a single cinema initially and expanding later
- **Impact:** FK commented out, will be activated once the Cines entity exists

### DT-03: Cascade on Delete
- **Date:** Week 18
- **Decision:** Apply cascade to all main relationships
- **Rationale:** Automatically maintain referential integrity
- **Impact:** Warn the user before deleting records with dependencies

### DT-04: Eager Loading by Default on Index Pages
- **Date:** Week 18
- **Decision:** Load relationships with with() in index() methods
- **Rationale:** Avoid the N+1 problem and improve performance
- **Impact:** More efficient queries, cleaner code

### DT-05: Parallel Task Distribution via Trello + Feature Branches
- **Date:** Week 16
- **Decision:** Assign a complete module (Model+Controller+Views) per member via Trello, each on their own feature branch
- **Rationale:** 
  - Maximize efficiency and avoid conflicts on the same file
  - Follow the team's usual Trello-based methodology
  - Ease task tracking and traceability
  - Work in parallel without blocking other members
- **Impact:** 
  - Faster, more organized development
  - Greater autonomy for each member
  - Better version control with feature branches
  - Eases code review and progressive integration

## ⚠️ Incidents and Resolutions

### Incident 1: Migration Order
- **Problem:** Error running migrations due to incorrect order
- **Solution:** Rename peliculas migrations with earlier timestamps
- **Status:** ✅ Resolved

### Incident 2: N+1 Problem on Index Pages
- **Problem:** Slow queries when listing sesiones
- **Solution:** Implement eager loading with with('sala', 'pelicula')
- **Status:** ✅ Resolved

### Incident 3: Optional Category Validation
- **Problem:** Error when creating a movie without categories
- **Solution:** 'nullable|array' validation and handling of an empty []
- **Status:** ✅ Resolved

### Incident 4: Hardcoded SQLite Configuration
- **Problem:** "attempt to write a readonly database" error during user registration
- **Diagnosis:** `config/database.php` had `'default' => 'sqlite'` hardcoded
- **Solution:** Changed to `'default' => env('DB_CONNECTION', 'mysql')` to read the environment variable
- **Impact:** Sessions and cache were also configured as 'file' instead of 'database'
- **Status:** ✅ Resolved

## 💭 Team Reflection on Phase 16-19

### Positive Aspects

This phase has been **very interesting** from a technical standpoint. We managed to implement complex relationships between entities (especially the N:M relationship between Películas and Categorías), and we learned to better manage SQL queries with techniques like eager loading to avoid performance issues.

**Working with Trello** and **feature branches** let us work in parallel without blocking each other, which was key to moving forward on the different modules.

### Difficulties and Delays

That said, we have to acknowledge that **this phase had significant difficulties and important delays**:

1. **Team availability:** Not the whole team was available at all times during these weeks. This meant some tasks depended on the work of members who weren't reachable.

2. **Task pile-up:** Tasks kept piling up, especially formal documentation (meeting minutes, follow-up reports). We prioritized working code over documentation, which is now generating documentation debt.

3. **Technical incidents:** We ran into complex issues (migration order, hardcoded SQLite config, N+1 problem) that ate up development time we hadn't planned for.

4. **Coordination:** Even using Trello, we had coordination issues when one member's tasks depended on another's work (for example, categories had to be created before películas could be fully implemented).

### Areas for Improvement Identified

**Once again, we think we need to manage class time better:**

- ✅ **Make better use of class hours** for tasks that need coordination or collective problem-solving
- ✅ **Hold short daily meetings** (daily standups) to catch blockers early
- ✅ **Document while developing**, not leave it for the end
- ✅ **Set shorter internal deadlines** to avoid pile-up
- ✅ **Improve how dependencies between tasks are defined** in Trello
- ✅ **Set aside specific time** for code review and branch integration

### Commitments for the Next Phases

1. **Attendance and availability:** Team commitment to be more available during class hours
2. **Time management:** Timeboxing tasks to keep them from dragging on
3. **Continuous documentation:** Each member documents their work as they develop it, not after
4. **Proactive communication:** Flag blockers or delays early
5. **Weekly review:** Meeting every Monday to review status and plan the week
